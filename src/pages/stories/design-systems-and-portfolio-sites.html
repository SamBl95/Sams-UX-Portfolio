Design systems and portfolio sites

Building a portfolio from scratch forces you to make decisions a design system usually makes for you. Colour tokens, type scales, spacing rhythms — when there's no system to inherit, you have to author one. This site became a miniature design system before it became a portfolio.

Constraints as a forcing function

The constraint was vanilla HTML and CSS: no component library, no utility framework, no design tokens from a tool like Tokens Studio. Every token had to be named, defined, and manually wired to the elements that consume it. That friction made the decisions deliberate in a way that reaching for a pre-built system rarely does.

What surprised me was how quickly a small set of well-named tokens became load-bearing. Once --color-accent existed, every CTA, focus ring, and hover state pointed at it. Changing the accent from forest green to deep teal took ten seconds and updated the whole site. That's the promise of design systems made visible at the smallest possible scale.

What carries over to product work

Token hygiene at portfolio scale directly translates to component library work. The discipline of asking "does this value belong in a variable or is it a one-off?" is the same question a systems designer asks before introducing a new token to a production library. Building small is a surprisingly honest rehearsal for building large.
