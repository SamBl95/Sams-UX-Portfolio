# Phase 15 — UI Design Contract

> Visual and interaction contract for Phase 15: Nav Hero Padding Fix.
> Generated by gsd-ui-researcher. Source of truth for the executor.

---

## Scope

This is a targeted CSS spacing fix. No new components, no new tokens, no layout changes.
The only permitted change is `padding-top` (and its responsive override) on `.about-hero` in `_about.css`.

---

## Problem Statement

**Bug:** The H1 on `about.html` and `cv.html` sits higher (closer to the nav bar) than on case study pages.

**Root cause:** Case study pages use `.cs-hero` which has an explicit `padding-top: var(--space-12)` (96px mobile / `var(--space-16)` 128px desktop) **plus** a `.cs-hero__back` back-link element before the H1. That back link has `margin-bottom: var(--space-8)` (64px) and its own line height (~20px), adding ~84px of vertical space before the H1.

About and CV pages use `.about-hero.section-lg` which gives `padding-block: var(--space-12)` (96px mobile) / `var(--space-16)` (128px desktop) — but the H1 is the first child with no preceding element, so it sits 84px higher than on case studies.

**Pages affected (broken):**
- `src/pages/about.html` — `.about-hero section-lg`
- `src/pages/cv.html` — `.about-hero section-lg`

**Pages that are correct (source of truth):**
- `src/pages/case-studies/cassi.html` — `.cs-hero`
- `src/pages/case-studies/i-exchange.html` — `.cs-hero`
- `src/pages/case-studies/community.html` — `.cs-hero` (assumed same pattern)

## Spacing Scale

Project 8pt scale — all tokens from `_variables.css`. No arbitrary pixel values permitted.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-8` | 64px | `.cs-hero__back` margin-bottom (reference, do not change) |
| `--space-10` | 80px | Candidate additional top padding increment |
| `--space-12` | 96px | `.section-lg` mobile padding-top (current on about/cv) |
| `--space-16` | 128px | `.cs-hero` desktop padding-top (source of truth) + `.section-lg` desktop |
| `--space-20` | 160px | `.section-xl` desktop padding (upper bound reference) |

**Target top-padding for `.about-hero`:**

The fix must override only `padding-top` (not `padding-bottom`) on `.about-hero`. The section retains `.section-lg` for `padding-bottom`.

| Breakpoint | Current effective padding-top | Target padding-top | Token |
|------------|-------------------------------|-------------------|-------|
| Mobile (< 905px) | `var(--space-12)` = 96px | `var(--space-12)` + back-link offset | See note below |
| Desktop (≥ 905px) | `var(--space-16)` = 128px | `var(--space-16)` + back-link offset | See note below |

**Measurement note for executor:** The exact token values must be confirmed by visual inspection in-browser at 375px and 1280px. The target is that the H1 baseline on `about.html` aligns with the H1 baseline on `cassi.html` when both are viewed at the same viewport width. The estimated offset is ~84px (64px `margin-bottom` + ~20px back-link line height). Suggested tokens to trial:

- Mobile: override to `var(--space-16)` (128px) then adjust if needed
- Desktop: override to `var(--space-20)` (160px) then adjust if needed

If no single token lands on the exact match, the **next larger token** is preferred over a smaller one — a consistent slightly-lower H1 is better than an inconsistent one.

Exceptions: none — no arbitrary pixel values permitted under any circumstance.

## Audit: Current Hero Structure Comparison

### Case Study Hero (source of truth — `.cs-hero`)

```
<section class="cs-hero">           ← padding-top: var(--space-12) mobile / var(--space-16) desktop
  <div class="cs-hero__inner container">
    <a class="cs-hero__back">       ← ~20px line height + margin-bottom: var(--space-8) = ~84px total
      ← Back to case studies
    </a>
    <h1 class="cs-hero__title">    ← H1 starts here, ~180px below nav bottom on mobile
```

### About / CV Hero (broken — `.about-hero.section-lg`)

```
<section class="about-hero section-lg">   ← padding-block: var(--space-12) mobile / var(--space-16) desktop
  <div class="container-content">
    <h1 class="about-hero__title">        ← H1 starts here, ~96px below nav bottom on mobile (84px too high)
```

### What Needs to Change

**File:** `src/styles/3-components/_about.css`
**Selector:** `.about-hero`
**Change:** Add `padding-top` override that compensates for the absent back-link vertical space.

The override must:
1. Apply only `padding-top` — `padding-bottom` stays controlled by `.section-lg`
2. Use a token from `--space-*` scale
3. Be responsive: one value for mobile, one for ≥ 905px
4. Not change anything on `.cs-hero`, `.section-lg`, or any other page

**Do NOT change:**
- `--nav-height` (56px)
- `.nav` height or any nav CSS
- `.section-lg` utility class (used by many pages)
- `padding-bottom` on `.about-hero`
- Any spacing on case study pages
