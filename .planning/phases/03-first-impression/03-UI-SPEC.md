**Accent (`--color-accent` / `--color-accent-accessible`) reserved for:**
1. Nav active state bottom border — `2px solid var(--color-accent)` (NAV-07)
2. Nav logo hover color
3. Focus outlines on all focusable nav elements — `2px solid var(--color-accent-accessible)`
4. Hero eyebrow text color — "Product Designer" label
5. Typewriter cursor block — `background-color: var(--color-accent)`
6. Typewriter typed text color — `color: var(--color-accent)` (Caveat span)
7. Primary CTA button fill (hero "See my work")

No second semantic color (destructive) is needed in this phase — there are no destructive actions.

**Nav scroll shadow** (NAV-08) — two-layer shadow, no new color token needed:
```
box-shadow: 0 1px 0 var(--color-border), 0 4px 16px -4px rgb(0 0 0 / 0.06);
```
The `rgb(0 0 0 / 0.06)` ambient shadow uses a raw alpha value — this is permissible as it is a shadow layer, not a surface color. Do NOT add a token for this.

## Interaction Contracts

### Nav — Desktop (905px+)

| State | Element | Visual change |
|-------|---------|---------------|
| Resting | `.nav__link` | `color: --color-text-secondary`, no background |
| Hover | `.nav__link` | `background-color: --color-surface` pill, `color: --color-text-primary`, `border-radius: --radius-md` |
| Active/current | `.nav__link[aria-current="page"]` | `background-color: --color-surface` pill + `border-bottom: 2px solid var(--color-accent)` |
| Focus | Any focusable nav element | `outline: 2px solid var(--color-accent-accessible)`, `outline-offset: 2px–3px`, `border-radius: --radius-sm` |
| Scrolled | `.nav--scrolled` (JS class on `.nav`) | `box-shadow: 0 1px 0 var(--color-border), 0 4px 16px -4px rgb(0 0 0 / 0.06)` |

**Transition on `.nav__link`:** `background-color var(--transition-fast), color var(--transition-fast)` — both properties listed explicitly (NAV-03). `--transition-fast: 150ms ease`.

**CTA in nav** — `.nav__link--cta` / `.nav .btn`:
- `margin-left: var(--space-3)` separating it from text links (NAV-05)
- Height override to 36px within `.nav` context only (NAV-06): `.nav .btn { height: 36px; }`
- Inherits button transition and active scale from `_button.css`

**Nav list gap:** `gap: var(--space-2)` (16px) at 905px+ (NAV-04, up from `--space-1`)

### Nav — Mobile (< 905px)

| State | Element | Visual change |
|-------|---------|---------------|

### Hero Entrance

5-element stagger on page load. `animation-fill-mode: both` on all elements.

| Element | Selector | Delay | Duration | Easing |
|---------|----------|-------|----------|--------|
| Eyebrow | `.hero__eyebrow` | 0ms | 600ms | `--ease-out-quint` |
| Headline | `.hero__headline` | 80ms | 600ms | `--ease-out-quint` |
| Typewriter container | `.hero__typewriter` (or parent `.hero__headline` — see note) | 160ms | 600ms | `--ease-out-quint` |
| Subheadline | `.hero__subheadline` | 240ms | 600ms | `--ease-out-quint` |
| CTAs | `.hero__actions` | 320ms | 600ms | `--ease-out-quint` |

**Current state vs. required:** `_hero.css` currently uses 60ms stagger steps (0/60/120/180ms) and has no typewriter-specific delay. Required (ANIM-02) is 80ms steps (0/80/160/240/320ms) with typewriter as a separate staggered element. The typewriter lives inside `.hero__headline` as an inline `<span>` — it cannot independently animate. The 5-element stagger applies to the 5 block-level BEM elements as listed. The typewriter starts animating its typing after an 800ms initial delay (already coded in `typewriter.js`), which naturally places it after the headline has settled.

**Animation keyframe** (update in `_hero.css`):
```css
@keyframes hero-enter {
  from { opacity: 0; transform: translateY(24px); }
  to   { opacity: 1; transform: translateY(0); }
}
```
Transform distance 24px — confirmed existing, keep. This is GPU-composited (transform + opacity only).

**Reduced motion:** `_reset.css` global rule sets `animation-duration: 0.01ms !important` — hero entrance is automatically suppressed. No additional per-element `@media` block needed for the entrance keyframe itself. The typewriter's `prefersReducedMotion` check is already in `typewriter.js`.

### Nav Mobile Menu Animation

| Property | From | To | Duration | Easing |
|----------|------|----|----------|--------|
| `opacity` | 0 | 1 | 200ms | `--ease-out` |
| `transform` | `translateY(-8px)` | `translateY(0)` | 200ms | `--ease-out` |

**Current state:** `_nav.css` has `@keyframes nav-menu-enter` with the correct from/to values but uses `120ms var(--ease-out)`. Required (ANIM-04) is `200ms --ease-out`. Update duration to `200ms`. Easing token is correct.

**Close animation:** No close animation currently. Mobile menu closes via `display: none` instantly. This is acceptable — close should be faster than open (asymmetric timing principle). No close animation is faster than any close animation. Confirmed: no close animation required by ANIM-04.
