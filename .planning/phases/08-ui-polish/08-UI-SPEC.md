## Interaction Contracts

This section is additional to the base template because this phase is interaction-heavy.

### UI-08: Nav link — left-to-right underline hover animation

Technique: pseudo-element `::after` sliding from `scaleX(0)` to `scaleX(1)` with `transform-origin: left`.

```
.nav__link::after {
  content: '';
  position: absolute;
  bottom: 0;
  left: 0;
  width: 100%;
  height: 2px;
  background-color: var(--color-accent-accessible);
  transform: scaleX(0);
  transform-origin: left center;
  transition: transform 200ms var(--ease-out);
}

@media (hover: hover) and (pointer: fine) {
  .nav__link:hover::after { transform: scaleX(1); }
}
```

The `.nav__link` itself must be `position: relative` to contain the `::after`.

Mobile: no underline animation — links are full-width block tap targets. The `::after` animation is scoped inside `@media (min-width: 905px)` and the hover media query.

### UI-08: Active state changes (replacing current background-color approach)

Remove at 905px+:
- `background-color: var(--color-surface)` on `.nav__link[aria-current="page"]`
- `border-bottom: 2px solid var(--color-accent)` on `.nav__link[aria-current="page"]`
- `border-radius: var(--radius-md)` on `.nav__link` at 905px+

Replace with at 905px+:
- `.nav__link[aria-current="page"]::after { transform: scaleX(1); }` — underline always visible on active
- `font-weight: var(--font-weight-semibold)` on `.nav__link[aria-current="page"]` (UI-09)

Mobile active state (unchanged behaviour): color remains `--color-text-primary`, weight becomes `--font-weight-semibold`.

### UI-07: Remove nav border-bottom

Remove `border-bottom: 1px solid var(--color-border)` from `.nav`. The `.nav--scrolled` scroll shadow is retained — it provides depth cue on scroll without a static border stroke.

### Animation timing

| Interaction | Duration | Easing |
|-------------|----------|--------|
| Nav underline enter | 200ms | --ease-out (cubic-bezier 0.23,1,0.32,1) |
| Nav underline exit | 200ms | --ease-out |
| Mobile menu enter (existing) | 200ms | --ease-out (unchanged) |

`prefers-reduced-motion` guard: wrap nav underline transition in `@media (prefers-reduced-motion: no-preference)` or add `transition: none` in the existing reduced-motion block.

## Structural Changes Contract

### Hero restructure (UI-01, UI-02, UI-03)

Current structure:
```
p.hero__eyebrow         "Product Designer"
h1.hero__headline       "The designer who [typewriter]"
p.hero__subheadline     "[one-liner paragraph]"
div.hero__actions       [buttons]
```

New structure:
```
h2.hero__name           "Sam Blake"           ← new element, accent color
h1.hero__headline       "A Product Designer who [typewriter]"
                                               ← h1 text changes; typewriter stays
div.hero__actions       [buttons]             ← subheadline REMOVED (UI-02)
```

Notes:
- The eyebrow `p.hero__eyebrow` is removed — "Sam Blake" as h2 replaces it as identity anchor
- `hero__subheadline` element is deleted from HTML (UI-02)
- `hero__subheadline` animation-delay stagger in `_hero.css` must be removed or reassigned
- The h1 text changes to begin "A Product Designer who..." — the typewriter suffix stays
- `hero__name` stagger order: name at 0ms, headline at 80ms, typewriter at 160ms, actions at 240ms

CSS for `.hero__name`:
```
.hero__name {
  font-family:    var(--font-heading);
  font-weight:    var(--font-weight-semibold);
  font-optical-sizing: auto;
  color:          var(--color-accent-accessible);
  letter-spacing: -0.02em;
  margin-bottom:  var(--space-3);
  line-height:    var(--leading-tight);
}
```

Size: use the h2 size from `_typography.css` — do NOT write a new font-size rule unless the existing h2 size is wrong in context. Check the rendered size at 1440px; if it overwhelms the h1, apply `--text-40` as a cap via a `.hero__name` override.

### Hero content width (UI-03)

Remove at `@media (min-width: 1440px)`:
- `max-width: var(--hero-content-max-width)` from `.hero__content`

Replace with:
- `width: 100%` (already on `.hero__content` — just remove the 1440px override)

The `--hero-content-max-width` token in `_variables.css` is then unused. Leave the token in place (it documents the old constraint and costs nothing). Do NOT delete it — future phases may reference it.

### Paragraph width removal (UI-04)

Remove `max-width: 72ch` from:
- `_about.css` — the `.about__body p` selector (line 75)
- `_case-study.css` — the `.case-study__body p` selector (line 283)
- `_stories.css` — the `.stories__body p` (or equivalent selector, line 122)

Do NOT remove `max-width` from:
- `.card__subtitle` (24ch) — card subtitle constraint is intentional for the card layout
- `.stat-block` metric label (18ch) — intentional chip sizing
- `.metrics-row` label (18ch) — intentional chip sizing

### Nav partial restructure (UI-05, UI-06)

Remove from `nav.html`:
```html
<a href="/" class="nav__logo" aria-label="Sam Blake — back to home">Sam Blake</a>
```

Add as first `<li>` in `.nav__list`:
```html
<li class="nav__item">
  <a href="/" class="nav__link{{#if navHome}} nav__link--active{{/if}}"
     {{#if navHome}} aria-current="page"{{/if}}>Home</a>
</li>
```

New nav link order: Home → Work → About → Stories → Get in touch (CTA)

The `navHome` flag is NOT set on any existing page (homepage uses `{{> nav}}` with no flag — correct, as Home is the page being viewed). Add `navHome=true` support in the partial for completeness, but no existing page sets it.

Push nav items right: without `.nav__logo` providing `margin-right: auto`, the `.nav__menu` needs `margin-left: auto` on the nav__menu element OR the first nav__item gets `margin-right: auto`. Preferred: `margin-left: auto` on `.nav__menu` at 905px+ to push the whole nav cluster right.

Remove from `_nav.css`: all `.nav__logo` rules (lines 34–55).

### Work page (UI-10, UI-11)

New file: `src/pages/work.html`

Register in `vite.config.js`:
```js
work: r('./src/pages/work.html'),
```

Nav partial: update Work link href from `/#case-studies` to `/src/pages/work.html`.

Page structure:
```html
{{> nav navWork=true}}
<main>
  <section class="work section-lg" aria-labelledby="work-heading">
    <div class="container">
      <h1 id="work-heading" class="work__heading">Selected work</h1>
      <p class="work__subheading">Three case studies from Santander UK</p>
    </div>
  </section>

  <section class="work__cases section-lg">
    <div class="container">
      <!-- feature section: one case study per row, image placeholder left, copy right -->
      <article class="work__feature"> ... </article>
      <article class="work__feature"> ... </article>
      <article class="work__feature"> ... </article>
    </div>
  </section>
</main>
```

Feature section layout spec (`.work__feature`):

- Desktop (905px+): two-column grid — left column 40% image placeholder / 60% copy column
- Mobile: single column, copy stacked below placeholder
- Gap between columns: `--space-8` (64px)
- Gap between feature rows: `--space-12` (96px)
- Image placeholder: `background-color: var(--color-surface)`, `border-radius: var(--radius-lg)`, aspect ratio 16/9, full column width
- Copy column: h2 case study title, metric chip (reuse `.card__metric-chip` BEM block), paragraph description, ghost CTA button linking to case study page

Focal point: the `h2` case study title inside the first `.work__feature` article is the primary visual anchor of the work page. It is the first heading after the `work__heading` h1, rendered at `--text-2xl` → `--text-3xl` in `--font-heading` (Fraunces), and establishes the visual hierarchy that cascading feature rows follow.

New CSS file: `src/styles/3-components/_work.css`
Import in `main.css` after `_case-studies.css`.

Work page title tag: `Work — Sam Blake | Product Designer`
Work page meta description: `Three product design case studies from Santander UK — delivering measurable outcomes across search, AI tooling, and community support.` (149 chars)
