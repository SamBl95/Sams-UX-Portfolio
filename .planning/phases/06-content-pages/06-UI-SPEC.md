Exceptions: `max-width: 72ch` on reading-width elements (`.post__body p`, `.case-study__body p`,
`.about-section__body p`) — `ch` unit is intentional for prose line-length, not a spacing override.

```css
/* Applied in _about.css, _stories.css, _case-study.css */
```

**Stories hover decision — background + border layer:**
Retain the existing `background-color: var(--color-accent-light)` hover on `.stories__link` as the
base layer. Add a `::before` pseudo-element as the left border reveal on top. The two layers
complement: the surface tint signals "this is interactive"; the border reveal adds directionality
and craft. Removing the background-color entirely would weaken hover affordance on touch fallback.

## Interaction Contract

### ANIM-05: Stories left-border accent reveal

**Mechanism:** `::before` pseudo-element on `.stories__link`, animated via `clip-path`.

```
Resting:  clip-path: inset(0 0 0 100%)   /* border fully clipped = invisible */
Hover:    clip-path: inset(0 0 0 0)       /* border fully revealed */
Duration: 200ms
Easing:   var(--ease-out)
```

**Exact CSS contract:**

```css
.stories__link {
  position: relative;   /* required for ::before positioning */
}

.stories__link::before {
  content:    '';
  position:   absolute;
  left:       calc(var(--space-2) * -1);  /* aligns to link's negative padding-inline */
  top:        0;
  bottom:     0;
  width:      3px;
  background: var(--color-accent-accessible);
  clip-path:  inset(0 0 0 100%);
  transition: clip-path 200ms var(--ease-out);
}

@media (hover: hover) and (pointer: fine) {
  .stories__link:hover::before {
    clip-path: inset(0 0 0 0);
  }
}
```

**Interaction with existing hover rule:** The existing `.stories__link:hover` background-color swap
uses `padding-inline: var(--space-2)` and `margin-inline: calc(var(--space-2) * -1)` to bleed
the hover area. The `::before` uses the same `left: calc(var(--space-2) * -1)` value so the
border sits at the edge of the expanded hover area. Both rules remain — they compose cleanly.

**Transition property on `.stories__link`:** Add `clip-path` to the existing `transition` shorthand,
or ensure the `::before` transition is self-contained on the pseudo-element (preferred — avoids
overwriting the parent transition).

**Reduced motion:** Add `.stories__link::before` to the `prefers-reduced-motion: reduce` block —
set `transition: none` and keep `clip-path: inset(0 0 0 0)` visible (no border hiding under
reduced motion; static border is not animation).

### LAY-03: Contact column constraint

**Mechanism:** New BEM element `.contact__column` wrapping CTAs, heading, and intro content.

**Decision rationale:** A BEM element (`.contact__column`) inside the contact block is preferred
over a `.container--reading` modifier for two reasons:
1. The `.container` modifier would apply globally to any container in this section, but only the
   CTA group needs constraining — the section heading and intro should behave normally.
2. BEM keeps layout scoped to the component, consistent with ITCSS conventions.

**Exact markup contract (`.contact` section):**

```html
<div class="contact__column">
  <h1 id="contact-heading" class="contact__heading">Get in touch</h1>
  <p class="contact__intro">...</p>
  <div class="contact__links">
    <a ... class="btn btn--primary">Email me</a>
    <a ... class="btn btn--secondary">Connect on LinkedIn</a>
  </div>
</div>
<div class="contact__interests">
  ...
</div>
```

**CSS contract:**

```css
.contact__column {
  max-width: var(--contact-column-max-width);  /* 600px */
}
```

The `.contact__interests` block sits outside `.contact__column` and is not width-constrained —
a list of short role descriptors does not need reading-width treatment.

**New token to add to `_variables.css`:**

```css
--contact-column-max-width: 600px;   /* contact page CTA column constraint */
```

Place in the "Component tokens" block alongside `--nav-height` and `--hero-content-max-width`.

### Scroll-reveal entrances

**Mechanism:** Existing `.js-reveal` + `data-reveal-delay` pattern from `_reveal.css` / `reveal.js`.
Animation: `translateY(20px)` → `translateY(0)`, opacity 0 → 1, 500ms `var(--ease-out-quint)`.

**Elements receiving `.js-reveal` per page:**

**About page (`about.html`):**

| Element | Class + delay |
|---------|--------------|
| `.about-hero` eyebrow + title (section as a whole) | `js-reveal` — no delay |
| `.about-hero__lede` | `js-reveal data-reveal-delay="100"` |
| Each `.about-section` | `js-reveal` — no delay (each is its own viewport trigger) |

**Contact page (`contact.html`):**

| Element | Class + delay |
|---------|--------------|
| `.contact__column` | `js-reveal` — no delay |
| `.contact__interests` | `js-reveal data-reveal-delay="100"` |

**Stories index (`stories/index.html`):**

| Element | Class + delay |
|---------|--------------|
| `.stories__heading` | `js-reveal` — no delay |
| `.stories__list` | `js-reveal data-reveal-delay="100"` |

**Stories post (`design-systems-and-portfolio-sites.html`):**

| Element | Class + delay |
|---------|--------------|
| `.post__date` + `.post__title` (parent wrapper if present) | `js-reveal` — no delay |
| `.post__body` | `js-reveal data-reveal-delay="100"` |

Granularity rule: one `.js-reveal` per visible section or content cluster — not per paragraph.
Per-paragraph reveal on long-form text causes distracting cascades and harms readability.
